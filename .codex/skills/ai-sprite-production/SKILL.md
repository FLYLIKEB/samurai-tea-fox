# AI 스프라이트 제작

무차우의 캐릭터, 타일, 오브젝트, UI, 아이콘, 이펙트 이미지를 AI로 하나씩 생성하거나 제작 절차를 정리할 때 사용한다. 목표는 `🎨 아트 에셋` DB의 한 행을 기준으로 생성·검수·반영 가능한 최종 PNG 또는 작은 스프라이트시트를 만드는 것이다.

## 정본

- 실제 제작 목록, 규격, 방향 수, 프레임 수, 제작 상태, 파일은 Notion `🎨 아트 에셋` DB가 정본이다.
- 시각 원칙은 Notion `09. 아트디렉션·맵·UI`를 따른다.
- 기술 적용은 Notion `12. 기술 스펙·아키텍처`와 현재 저장소 구조를 따른다.
- 캐릭터 정체성은 관련 캐릭터 DB 행을 읽어 반영한다. 예: `무차우`는 인간·구미호 혼혈, 붉은여우 큰 귀와 꼬리, 검, 차통과 다구가 핵심이다.
- 이미지 생성, PixelLab, 스프라이트 제작 프롬프트를 만들 때는 먼저 `assets/style/art-style-tokens.json`을 읽는다. 색상 팔레트, 공통 시각 컨셉, positive/negative 토큰은 이 파일을 정본으로 사용하고 스킬 문서에 복제하지 않는다.
- 캐릭터나 오브젝트의 걷기, idle, 공격, 피격, 상호작용 같은 움직임 프레임이 필요하면 `pixellab-animation-production`을 함께 사용한다. 움직임 스프라이트는 일반 이미지 생성보다 PixelLab 애니메이션·캐릭터 endpoint를 우선한다.

## 작업 단위

- 한 작업은 가능하면 `아트 에셋 DB 행 1개 = AI 생성 작업 1개 = 검수된 파일 1개 또는 작은 스프라이트시트 1개`로 제한한다.
- 대량 생성이 필요하면 스타일 기준 샘플을 먼저 확정한 뒤, 캐릭터/타일/UI처럼 서로 다른 검수 기준을 가진 묶음으로 나눈다.
- 코드 작업이나 저장소 반영이 포함되면 `isolated-worktree-pr` 흐름에 따라 전용 branch/worktree에서 작업하고 PR 단위로 머지한다.

## 제작 순서

1. `🎨 아트 에셋` DB에서 대상 행을 고르고 `이름 / 종류 / 가로(px) / 세로(px) / 방향 수 / 프레임 수 / 바이옴 / 연결형 / 연결 규칙 / 팔레트·형태 / 비고`를 확인한다.
2. 관련 캐릭터, 지역, 몬스터, 아이템, 차, 요술, 던전 relation이 있으면 필요한 행만 fetch해서 실루엣과 용도를 확인한다.
3. `assets/style/art-style-tokens.json`의 해당 `asset_profiles`와 기본 positive/negative 토큰을 읽는다.
4. 프롬프트에는 목적, 캔버스 크기, 방향, 프레임 수, 배경 투명 여부, 실루엣 우선순위, 금지 요소를 명시한다. 움직임·방향 세트가 포함되면 `pixellab-animation-production`의 인증 확인, endpoint 선택, 비동기 job polling, 프레임 검수 기준을 따른다.
5. 여러 후보를 생성하되, 최종 후보만 런타임 에셋 경로에 넣는다. AI 생성 원본 raw와 중간 후보는 모두 Git에서 제외된 `assets/source/imagegen/` 아래에 저장한다.
6. Godot 또는 에셋 브라우저에서 실제 크기와 정수 배율로 확인한다.
7. 통과한 파일 경로와 검수 메모를 `🎨 아트 에셋` DB의 `파일`, `제작 상태`, `비고`에 반영한다.

## 생성 기준

- 기본 그래픽은 32x32 기반 저해상도 픽셀아트, nearest filtering, 정수 배율을 전제로 한다.
- 과한 음영보다 윤곽선, 형태 구분, 단순한 실루엣을 우선한다.
- 캐릭터는 큰 귀와 꼬리, 방향성, 포즈가 작은 크기에서도 먼저 읽혀야 한다.
- 타일은 단품 아이콘이 아니라 연결됐을 때 자연스러운지 검수한다. 강, 숲, 산, 광산은 경계와 연결 방향을 고려한다.
- UI/HUD는 맵을 가리지 않는 단순한 픽셀 패널과 가장자리 배치를 우선한다.
- 상시 스탯 표시는 `HP / 기운 / 心` 3개로 고정한다. `MP`, `SP`, stamina, hunger, thirst, temperature, fatigue 게이지나 아이콘을 추가하지 않는다.
- 전투 이펙트는 저채도, 짧은 잔상, 비대칭, 끊긴 선, 연기·김·먹빛 계열을 우선한다. 거대한 마법진, 전신 오라, 네온 발광, 화면 전체 폭발은 기본 미학에서 제외한다.

## 로컬 경로

- 캐릭터와 오브젝트: `assets/sprites/`
- 타일: `assets/tiles/`
- UI와 아이콘: `assets/ui/`
- AI 생성 raw와 중간 후보: `assets/source/imagegen/` (Git 제외)
- 제작용 스타일 토큰: `assets/style/art-style-tokens.json`
- 에셋 점검 도구: `tools/asset_browser/`

파일명은 가능하면 안정적인 asset ID와 용도를 드러내게 한다. 예: `art-8_fox_samurai_walk_4dir_32.png`.

## 검수 체크리스트

- 지정된 `가로(px)`와 `세로(px)`를 지켰는가.
- 프레임 수와 방향 수가 DB 행과 맞는가.
- 투명 배경이 필요한 에셋에 배경색이 남아 있지 않은가.
- anti-aliasing, 흐릿한 edge, 실사 질감, 워터마크, 텍스트가 없는가.
- 1x와 2x 정수 배율에서 실루엣과 방향이 읽히는가.
- 팔레트와 채도가 `assets/style/art-style-tokens.json`의 범위에서 벗어나지 않는가.
- Godot import에서 nearest filtering과 픽셀 정렬이 깨지지 않는가.
- DB의 제작 상태와 파일 경로가 실제 로컬 상태와 일치하는가.

## 보고

완료 보고에는 대상 Notion 행, 생성된 파일 경로, 사용한 프롬프트 또는 프롬프트 출처, 검수 방법, 남은 수정 필요 사항을 포함한다. 테스트용 임시 이미지는 제작 완료 에셋처럼 보고하지 않는다.
