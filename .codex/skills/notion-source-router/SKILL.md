# Notion 정본 라우팅

이 프로젝트의 Notion 문서를 읽을 때 사용한다. 목적은 모든 문서를 한꺼번에 읽지 않고, 현재 작업에 필요한 정본만 읽어 충돌과 컨텍스트 낭비를 줄이는 것이다.

## 기본 읽기 순서

1. `무사여우: 한 잔의 도 — 게임 컨셉 바이블`
2. `00. 기획 아키텍처·정본 규칙`
3. `12. 기술 스펙·아키텍처`
4. 현재 `🤖 AI 구현 백로그` 항목
5. 선택한 항목의 `관련 기획` 문서
6. 선택한 항목의 `관련 데이터` DB

## 정본 선택 규칙

- 정보를 어디에 둘지 판단할 때는 `00. 기획 아키텍처·정본 규칙`을 우선한다.
- 어떻게 구현할지 판단할 때는 `12. 기술 스펙·아키텍처`를 우선한다.
- 다음에 무엇을 구현할지는 `🤖 AI 구현 백로그`를 우선한다.
- 왜 그런 게임 규칙인지 확인할 때는 해당 시스템 설계 문서를 읽는다.
- 어떤 콘텐츠가 존재하는지 확인할 때는 해당 콘텐츠 DB를 읽는다.
- 정확한 수치와 공식은 `⚖️ 밸런스 상수` 또는 해당 콘텐츠 DB를 읽는다.
- 그래픽 제작 단위는 `🎨 아트 에셋` DB를 읽는다.
- 캐릭터, 맵, 맵 내 사물의 시점·방향 규칙은 `09. 아트디렉션·맵·UI`와 `assets/style/art-style-tokens.json`의 정면 우선 탑뷰 규칙을 함께 확인한다. 캐릭터 이동용 방향 세트가 명시된 작업만 정면 원본 기반 좌·우·후면 예외를 적용한다.

## 충돌 우선순위

충돌하는 정보가 있으면 다음 순서로 판단한다.

1. `00. 기획 아키텍처·정본 규칙`
2. `12. 기술 스펙·아키텍처`
3. 현재 백로그 이슈의 명시적 요구사항
4. 해당 시스템 설계 문서
5. 해당 콘텐츠·밸런스 DB
6. 오래된 설명이나 예시 문구

정확한 콘텐츠 값과 수치는 항상 해당 DB가 우선이다.

## 금지

- 백로그 항목과 관련 없는 설계 문서를 연쇄적으로 읽지 않는다.
- 문서의 설명 값을 코드나 다른 문서에 복제하지 않는다.
- 요구사항이 불명확할 때 오래된 서술이나 기억으로 보완하지 않는다. 정본을 다시 확인한다.
