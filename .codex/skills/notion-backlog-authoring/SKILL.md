# Notion 백로그 항목 작성

`🤖 AI 구현 백로그`에 새 작업을 만들거나 기존 항목을 AI 실행 가능한 단위로 보강할 때 사용한다. 목표는 한 항목이 독립 PR 하나로 끝날 수 있을 만큼 명확하게 만드는 것이다.

## 필수 필드

백로그 항목에는 다음 내용을 채운다.

- `목표`: 이번 작업으로 달성할 사용자/프로젝트 결과
- `범위`: 이번 PR에서 실제로 구현할 내용
- `비범위`: 이번 PR에서 의도적으로 하지 않을 내용
- `완료 조건`: 완료라고 판단할 관찰 가능한 조건
- `검증 방법`: 실행할 테스트, 빌드, 수동 확인
- `AI 실행 프롬프트`: Codex가 그대로 따라도 되는 작업 지시
- `선행 작업`: 막힘 여부를 판단할 dependency
- `예상 변경 영역`: 주요 파일, 모듈, 데이터
- `PR 원칙`: PR 크기, 리뷰 포인트, 금지할 scope creep

## 작성 규칙

- 한 항목은 가능하면 S/M 크기의 독립 PR 하나로 끝나게 쓴다.
- L 작업은 수직 슬라이스가 목적이 아니라면 하위 S/M 작업으로 나눈다.
- 개별 콘텐츠는 문서 본문이 아니라 해당 콘텐츠 DB 행으로 둔다.
- 숫자와 공식은 `⚖️ 밸런스 상수` 또는 해당 콘텐츠 DB 컬럼에 둔다.
- 기획 문서를 코드나 백로그에 길게 복제하지 말고 관련 정본 링크를 둔다.
- 완료 조건은 “구현한다”가 아니라 테스트 가능하거나 확인 가능한 상태로 쓴다.

## 품질 점검

- 범위와 비범위가 충돌하지 않는지 확인한다.
- 선행 작업이 모호하면 실행 가능한 상태로 보지 않는다.
- 검증 방법이 없는 항목은 구현 준비가 부족한 것으로 본다.
- AI 단독 실행 가능 여부는 권한, 외부 의존성, 시각 검수 필요성까지 고려해 판단한다.
